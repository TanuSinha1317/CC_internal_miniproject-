1. Executive Summary & Project Objectives

In modern programming language processing, the Lexical Analysis phase acts as the foundational gateway between unformatted, continuous character sequences and structured syntax graphs. This project presents a full-featured, robust, and mathematically sound lexical scanner engineered for MiniLang—a custom context-free imperative mini-language designed for academic study.

The implementation converts raw source files into discrete, strongly-typed Tokens, logs coordinate tuples (Line, Column), constructs an intelligent Symbol Table with type and value inference, captures syntax anomalies via a non-halting Lexical Error Registry, and exposes the engine through both a high-throughput Node.js microservice and an isomorphic, zero-dependency browser client.

4. Core Lexer Implementation & Lookahead DFA Engine

The scanner (backend/lexer/Lexer.js) employs a Deterministic Finite Automaton (DFA) model that guarantees linear O(N) scanning time over input length.

1. Lookahead Buffer: Methods peekChar() and peekNextChar() read ahead by 1 character without consuming the stream, enabling decisive branching between single-character operators (=, >, <) and composite two-character tokens (==, >=, <=, !=, &&, ||).

2. Coordinate Tracking: Stream traversal rigorously updates line on \n carriage returns and resets column = 1, enabling industrial-standard compiler diagnostics.

3. High-Efficiency Keyword Lookup: Utilizes JavaScript ES6 Set.has() hashing rather than iterative regex checking, completing keyword identification in O(1) constant time.

// MiniLang Representative Program Trace START INT age = 20; FLOAT marks = 89.5; STRING name = "Tanu"; IF age >= 18 THEN PRINT("Eligible"); ELSE PRINT("Not Eligible"); ENDIF END
Scanner Non-Crashing Guarantee: When an unmapped symbol is detected, the lexer delegates to addError() and smoothly continues character consumption without throwing unhandled exceptions.

5. Symbol Table Design & Contextual Attribute Inference

The Symbol Table (backend/lexer/SymbolTable.js) serves as the persistent repository of identifiers discovered throughout the program lifecycle. Rather than acting as a static identifier bag, it implements early semantic inference:

• Primary Hash Key: Uniquely indexed by variable name via an internal Map data structure, guaranteeing duplicate suppression and O(1) access.

• Type Backtracking: When scanning token IDENTIFIER at position i, the symbol processor inspects token[i-1]. If the preceding lexeme belongs to primitive types {INT, FLOAT, STRING}, the symbol's dataType is populated accordingly.

• Value Forward-Lookahead: Upon encountering assignment pattern ID = LITERAL;, the system extracts the literal value into the table.

Symbol Invariant: Subsequent references to declared identifiers preserve original definition coordinates while facilitating forward semantic validation.
6. Lexical Error Handling & Panic-Mode Recovery

Industrial compilers must diagnose source syntax defects without crashing mid-stream. MiniLang embeds a specialized Lexical Error Registry categorizing five major fault domains:

Error Classification Erroneous Sample Diagnostic Explanation Recovery Action
INVALID_CHARACTER @, $, #, ~ Foreign character outside MiniLang alphabet Record error; skip 1 char; continue
INVALID_IDENTIFIER 123age, 9count Identifier unlawfully begins with numerical digit Consume full alphanumeric token; mark error
UNTERMINATED_STRING "Tanu;\n Newline or EOF encountered before closing quote " Halt string state; log error; resume on newline
MALFORMED_NUMBER 89.5.2, 10. Floating-point literal with multiple dots or trailing period Isolate malformed literal; flag error state
INVALID_SYMBOL ! (isolated) Single exclamation not paired with = (suggest !=) Log warning; advance cursor

8. Software Engineering & Dual-Tier Client-Server Architecture

The system was built following modern decoupled full-stack paradigms. The backend features an Express.js REST endpoint (POST /api/analyze) delivering JSON token arrays. Simultaneously, the frontend (frontend/script.js) houses an isomorphic duplicate ClientLexer. In the event of network disruption, backend downtime, or offline execution, the frontend automatically falls back to client-side parsing without UX degradation.

9. Compiler Phases Roadmap

This project provides the foundational tokens for subsequent compiler phases:

  • Phase 2 (Syntax): Recursive Descent / LL(1) AST builder.
  • Phase 3 (Semantic): Type compatibility and scope checking.
  • Phase 4 (Intermediate): Three-Address Code (TAC) Quadruples.
  • Phase 5 (Optimization): Constant folding & dead code elimination.
  • Phase 6 (Target Code): WebAssembly / x86 Assembly synthesis.
